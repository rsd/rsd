# BUG-0001: SSH "Connection to ... closed." Noise in Recipe Output

**Fixed in**: v1.22.0
**Files**: `lib/protocol.lib`, `lib/io.lib`
**Symptoms**: Every SSH command produced `Connection to flow.jumba.com.br closed.` lines in framed task output, sometimes unframed (directly on terminal).

## Root Cause

OpenSSH prints `Connection to <host> closed.` to **stderr** when a session ends.
This message is generated by the **local SSH client process**, not the remote side.

Two paths leaked this noise:

1. **Framed output** — The message went through `frame_lines` process substitution.
   A filter was added but initially didn't work because...

2. **Unframed output** — With SSH `-t` (PTY allocation), the close message is
   written to stderr **asynchronously after the PTY channel teardown**. By the
   time it arrives, the process substitution pipe (`2> >(frame_lines)`) may have
   already closed its read end. The message then falls through to the real
   terminal stderr, bypassing all filtering.

## Fix

**Kill the noise at the source**, not after the fact:

```bash
# protocol.lib — SSH protocol handler
local -a ssh_opts=("-o" "LogLevel=ERROR")
```

`LogLevel=ERROR` tells OpenSSH to suppress all informational messages (including
the connection close notification). Only actual errors are printed.

Additionally, `frame_lines` retains its filter as defense-in-depth, plus a
consecutive empty line deduplicator for PTY buffer artifacts.

## Test

```bash
bats tests/unit/io_lib.bats
```

Tests cover: SSH noise filtering, empty line suppression after noise, consecutive
empty line dedup, partial-match rejection, various hostname formats.

## Regression Risk

- Adding new SSH options that reset `LogLevel` (e.g., `-v` for verbose).
- Refactoring `ssh_opts` initialization to an empty array without the default.
- Using a different SSH wrapper that doesn't honor `-o LogLevel=ERROR`.
